1What is a Support Vector Machine?

A Support Vector Machine (SVM) is a supervised machine learning algorithm designed to find the optimal decision boundary — called a hyperplane — that separates data points belonging to different classes with the maximum possible margin. It was introduced by Cortes & Vapnik (1995) and remains one of the best-performing classifiers for high-dimensional, moderate-sized datasets, which is exactly the regime encountered in website fingerprinting.

The Margin Maximisation Principle

Given a set of labelled training points, there are infinitely many hyperplanes that correctly separate the classes. SVM selects the unique hyperplane that maximises the margin — the perpendicular distance between the hyperplane and the closest data points of each class. Those closest points are called support vectors, and they are the only training examples that actually determine the decision boundary. All other training points are irrelevant once the model is trained.

Binary SVM optimisation problem (primal form) Minimise: (1/2) ‖w‖² + C · Σᵢ ξᵢ Subject to: yᵢ(wᵀxᵢ + b) ≥ 1 − ξᵢ for all i ξᵢ ≥ 0 for all i
w — Weight vector
Normal to the separating hyperplane. Its magnitude controls margin width: larger ‖w‖ = narrower margin = harder boundary.
b — Bias term
Shifts the hyperplane away from the origin. Learnt during training alongside w.
C — Regularisation parameter
Trades off margin width vs misclassification penalty. Large C = hard margin (fits training data closely). Small C = soft margin (wider, more robust).
ξᵢ — Slack variables
Allow some training points to violate the margin (soft-margin SVM). Essential for real-world noisy data.
Decision Rule at Inference

Given a new, unseen feature vector x, the SVM computes its decision function:

Decision function f(x) = sign( wᵀx + b ) = sign( Σᵢ αᵢ yᵢ K(xᵢ, x) + b )

The sign of f(x) determines the predicted class. The magnitude of f(x) is proportional to confidence. In this project, predict_proba() (Platt scaling) is enabled via probability=True to produce calibrated probability scores for ROC curve generation.

2The Kernel Trick & Why RBF is Used

Website traffic traces are not linearly separable in the original 104-dimensional CUMUL feature space. Different websites produce overlapping traffic patterns when viewed as linear combinations of their features. The kernel trick solves this by implicitly mapping data into a much higher-dimensional (potentially infinite-dimensional) feature space where linear separation becomes possible — without ever computing the high-dimensional coordinates explicitly.

Kernel function definition K(xᵢ, xⱼ) = φ(xᵢ)ᵀ φ(xⱼ) ← computes dot product in high-dim space without computing φ(x) explicitly
The RBF (Gaussian) Kernel

This project uses the Radial Basis Function (RBF) kernel, also called the Gaussian kernel. It is the default choice in the Panchenko et al. (2016) CUMUL paper and remains the most commonly used kernel in practice for traffic analysis tasks.

RBF kernel formula K(xᵢ, xⱼ) = exp( −γ · ‖xᵢ − xⱼ‖² ) γ (gamma): controls how fast similarity decays with distance Small γ → wide Gaussian → far points still similar → smoother boundary Large γ → narrow Gaussian → only very close points similar → complex boundary
Why RBF over Linear kernel?

Linear SVM assumes CUMUL features are linearly separable — i.e., a website's traffic fingerprint is a linear combination of its packet counts and directions. In practice this is false: subtle non-linear relationships between cumulative curve shape, burst patterns, and total volume are what distinguish similar sites. RBF captures these non-linear boundaries.

Why RBF over Polynomial kernel?

Polynomial kernels have an additional degree hyperparameter and are numerically less stable. They also tend to overfit more aggressively at high degrees. RBF is controlled entirely by γ and C, making it easier to tune, more stable, and empirically superior on traffic fingerprinting datasets per the original CUMUL paper.

Key insight: RBF in the context of CUMUL features
The 104-dim CUMUL vector encodes the shape of a traffic trace as sampled points along the cumulative curve C(T). Two visits to the same site produce vectors that are geometrically close in ℝ¹⁰⁴ but rarely identical (network jitter, CDN variation). The RBF kernel's Euclidean distance measure ‖xᵢ − xⱼ‖² is therefore a natural similarity metric: two traces from the same site will have small distance, yielding high K(·,·) ≈ 1, while traces from different sites will have large distance, yielding K(·,·) ≈ 0.
3Multiclass SVM — One-vs-One Strategy

The original SVM formulation is binary (two classes). This project classifies up to 100 monitored websites simultaneously. Scikit-learn's SVC handles this automatically using the One-vs-One (OvO) strategy.

One-vs-One (OvO) Decomposition
How OvO works for 100 classes
For N=100 monitored sites, OvO trains N(N−1)/2 = 4,950 binary classifiers, one for every pair of classes. During prediction, each of the 4,950 classifiers casts one vote. The class receiving the most votes wins. Scikit-learn implements this efficiently without explicitly iterating 4,950 times at inference — it uses a single kernel matrix computation.
Number of binary classifiers for N classes (OvO) N_classifiers = N × (N − 1) / 2 For N = 100: 100 × 99 / 2 = 4,950 classifiers For N = 10: 10 × 9 / 2 = 45 classifiers
Why OvO rather than One-vs-Rest (OvR)?
OvO trains on smaller subsets (only samples from 2 classes at a time), so each binary SVM converges faster. OvO is also less sensitive to class imbalance — a concern when some monitored sites have fewer captures than others. For SVMs specifically, OvO is generally more accurate than OvR because each sub-classifier focuses on a well-defined two-class boundary.
Implication for training time
OvO with 100 classes means kernel matrix computations are replicated 4,950 times internally. This is the primary reason why training with 100 sites and 50 instances per site (5,000 training samples × 104 features) takes several minutes. GridSearchCV compounds this: 7 C values × 7 γ values × 10 CV folds × 4,950 classifiers = 2,425,500 binary SVM fits.
4Feature Pipeline — From Raw Packets to SVM Input

The SVM does not operate on raw network packets. The CUMUL algorithm transforms each traffic trace into a fixed-length numerical vector that the SVM can process. Understanding this pipeline is essential to understanding why the SVM performs the way it does.

Step-by-step pipeline
1
Raw PCAP → Signed packet sequence T
Each packet's size is assigned a sign based on direction: positive (+) for server→client (incoming data), negative (−) for client→server (requests/ACKs). Direction is determined by IP.dst == '127.0.0.1' (loopback address of the Tor SOCKS proxy).
T = [+1024, −64, +512, −32, +2048, −96, +768, ...]
2
Build cumulative curve C(T)
Compute two running totals over T: aᵢ = Σ|pⱼ| (total bytes transferred — x-axis, always increases) and cᵢ = Σpⱼ (net signed sum — y-axis, rises on incoming, falls on outgoing). Together (aᵢ, cᵢ) define the cumulative curve C(T) starting at (0,0). The slope of C(T) reflects traffic direction; plateaus indicate bursts of one-directional traffic.
3
Interpolate to 100 equidistant points
Different visits to the same website produce traces of different length (different number of packets). To get a fixed-length representation, 100 x-positions are chosen uniformly from 0 to a_max using np.linspace(0, a_max, 100). The corresponding c-values are read off C(T) via piecewise-linear interpolation (np.interp()). This produces a 100-element vector encoding the shape of the curve regardless of total trace length.
4
Append 4 global statistics
Four scalar features are concatenated: Nᵢₙ (incoming packet count), Nₒᵤₜ (outgoing packet count), Sᵢₙ (total incoming bytes), Sₒᵤₜ (total outgoing bytes). These capture absolute scale information that the normalised curve shape cannot encode.
5
MinMaxScaler normalisation → [−1, 1]
The 104-dim vector is normalised feature-by-feature to the range [−1, 1] using MinMaxScaler(feature_range=(−1, 1)). The scaler is fit only on training data to prevent data leakage. Test data is transformed using the training min/max. This is critical for RBF SVM: the kernel computes Euclidean distances, so features with different scales would dominate inappropriately if not normalised.
6
LabelEncoder → integer class indices
String site labels (e.g. "bbc", "cnn") are encoded to integer indices (0, 1, 2, ..., N−1) by LabelEncoder.fit(selected_labels). The encoder is fitted on all selected labels (not just those appearing in training data) to ensure consistent index mapping at test time. Predictions are decoded back to string labels via inverse_transform().
What the 104 dimensions represent
Dimensions Feature group What it encodes Why it matters to the SVM
[0:100] CUMUL interpolation points The shape of the C(T) cumulative curve sampled at 100 equidistant total-byte positions Encodes the site's characteristic traffic pattern: direction shifts, burst timing, ratio of download to upload. RBF kernel compares these shapes via Euclidean distance.
[100] Nᵢₙ — incoming count Total number of incoming TCP packets in the trace Sites with many small objects (ads, trackers) vs few large objects (video) differ strongly here.
[101] Nₒᵤₜ — outgoing count Total number of outgoing TCP packets (requests, ACKs) Correlates with number of HTTP requests; distinguishes single-page vs multi-resource sites.
[102] Sᵢₙ — incoming bytes Total incoming payload bytes Site total page weight; distinguishes lightweight blogs from heavy news portals.
[103] Sₒᵤₜ — outgoing bytes Total outgoing payload bytes Encodes total request size; combined with Sᵢₙ gives an upload/download ratio signal.
5Hyperparameters — C, γ, and Their Roles

The RBF SVM has two critical hyperparameters: C (regularisation) and γ (gamma) (kernel bandwidth). Their interaction determines everything about the classifier's generalisation ability. The values used in this project follow the search ranges specified in the original Panchenko et al. paper.

C — Regularisation Strength
C [2¹¹ … 2¹⁷] = [2048, 4096, 8192, 16384, 32768, 65536, 131072] — 7 values searched by GridSearchCV
Effect of C on the SVM boundary Small C (e.g. 0.1) → Wide margin, many misclassified training points, high bias Large C (e.g. 2¹⁷) → Narrow margin, few misclassified points, may overfit (high variance) Optimal C → Maximises generalisation on unseen traffic traces
Why such large C values (2¹¹ to 2¹⁷)?
Traffic fingerprinting data is relatively clean and consistent within each class — the same website visited repeatedly produces highly similar CUMUL curves, especially after Tor circuit rotation and validation (MIN_PACKETS=500). This means a hard or near-hard margin (large C) is appropriate: the SVM should commit to tight class boundaries rather than allowing many misclassifications. The paper's original authors empirically determined this range is optimal for their dataset, and this project replicates those ranges.
γ (gamma) — RBF Kernel Bandwidth
gamma [2⁻³ … 2³] = [0.125, 0.25, 0.5, 1.0, 2.0, 4.0, 8.0] — 7 values searched by GridSearchCV
Effect of γ on the RBF kernel K(xᵢ, xⱼ) = exp(−γ · ‖xᵢ − xⱼ‖²) Small γ (0.125) → Wide Gaussian. Distant points still influence each other → smooth boundary Large γ (8.0) → Narrow Gaussian. Only very close points influence → spiky, complex boundary
γ too small → underfitting
All 104-dim CUMUL vectors look similar to each other. The RBF kernel cannot distinguish different websites. Decision boundaries become very broad and inaccurate. The model predicts the most common class for almost everything.
γ too large → overfitting
Each training point becomes its own island. The model memorises training traces exactly but fails on test traces (even from the same website) because real captures always differ slightly due to CDN variation and network jitter.
Fallback defaults (no grid search)
SVM_C 1.0 Default when grid_search=False or min class size < 2. Standard sklearn default.
SVM_GAMMA "scale" = 1 / (n_features × X.var()) = 1 / (104 × variance of training data). Auto-scales to feature space.
probability True Enables Platt scaling (cross-validated logistic regression on decision scores) to produce calibrated probability outputs. Required for ROC curves and confidence histograms. Adds ~5× training time cost.
CV_FOLDS 10 10-fold StratifiedKFold cross-validation during GridSearchCV. Capped at min(10, min_class_size) to avoid empty folds.
6GridSearchCV — Automated Hyperparameter Tuning

Rather than manually picking C and γ, this project uses GridSearchCV to exhaustively evaluate every combination in the paper's search space. The best combination is chosen based on cross-validation accuracy on the training set — the test set is never seen during this process.

Search grid definition (from config.py)
# config.py — exact values used

GRID_SEARCH_GAMMA = [2**i for i in range(-3, 4)] # [0.125, 0.25, 0.5, 1.0, 2.0, 4.0, 8.0]
CV_FOLDS          = 10

param_grid = {

best_model  = search.best_estimator_
best_params = search.best_params_           # {"C": ..., "gamma": ...}
best_score  = search.best_score_            # mean CV accuracy at best params
Total fits = combinations × folds
GridSearchCV computational cost Total SVM fits = |C| × |γ| × k_folds = 7 × 7 × 10 = 490 SVM fits Each fit trains on 90% of training data (9/10 folds) Each fit validates on 10% of training data (1/10 fold) Best (C, γ) → retrained on 100% of training data → final model
Stratified K-Fold — why stratification matters
StratifiedKFold preserves class proportions in each fold
With 100 classes and 50 training instances per class (5,000 total), a standard KFold split might accidentally put all instances of a rare site in the validation fold, leaving the training fold with zero examples of that class. StratifiedKFold guarantees each fold contains approximately the same proportion of each class as the full training set — approximately 5 instances per class per fold in a 10-fold split.
Guard: minimum class size check
# svm_model.py — _fit_estimator(): guard against tiny classes
class_counts = Counter(y_train)
min_class    = min(class_counts.values())
cv_folds     = min(config.CV_FOLDS, min_class)  # cannot have more folds than min class size

if cv_folds < 2:
    # Grid search not possible — fall back to direct fit with defaults
    model = SVC(kernel="rbf", probability=True, C=config.SVM_C, gamma=config.SVM_GAMMA)
    model.fit(X_train_scaled, y_train_enc)

    # and test (next test_instances files) per site.

    # ── STEP 5: SVM fit (GridSearchCV or direct) ──────────────────────
    # Internally: GridSearchCV(SVC(rbf), param_grid, StratifiedKFold(10))

    cv_model  = SVC(kernel="rbf", probability=True, C=model.C, gamma=model.gamma)
    cv_scores = cross_val_score(cv_model, X_train_scaled, y_train_enc, cv=cv_folds)

_score_matrix() — confidence score extraction
def _score_matrix(model, X):
    # Priority 1: predict_proba() — Platt-scaled probabilities (best for ROC)
    if hasattr(model, "predict_proba"):
        return model.predict_proba(X)            # shape: (N, n_classes)

    # Priority 2: decision_function() — raw SVM margin distances
    if hasattr(model, "decision_function"):
        scores = model.decision_function(X)     # shape: (N,) binary or (N, k) OvO
        if scores.ndim == 1:
            scores = np.vstack([-scores, scores]).T
        return scores

    # Priority 3: one-hot hard predictions (fallback)
    preds  = model.predict(X)
    out    = np.zeros((len(preds), n_classes), dtype=float)
    for i, pred in enumerate(preds):
        out[i, list(model.classes_).index(pred)] = 1.0
    return out
8Strengths of SVM for Website Fingerprinting
✦High-dimensional effectiveness
  • SVM is theoretically guaranteed to find the optimal margin in any number of dimensions. The 104-dim CUMUL space is well within its operating envelope — SVMs routinely excel in spaces with thousands of features.
  • Many ML methods (e.g. k-NN, naive Bayes) degrade sharply as dimensionality increases. SVM's margin-based geometry is immune to the curse of dimensionality in the regime where N_features < N_samples.
✦Strong generalisation from sparse data
  • With only 50 training instances per website (vs 100-class problem), the dataset is very sparse. SVM's maximum-margin principle explicitly optimises generalisation, not just training accuracy.
  • The support vector solution depends only on the few most informative training examples, making it robust to the majority of "easy" samples and focusing on class boundaries.
✦Kernel flexibility
  • The RBF kernel implicitly maps 104-dim CUMUL vectors into an infinite-dimensional Hilbert space, capturing non-linear traffic pattern relationships that no linear model could express.
  • The kernel is computed as a simple exponentiated distance — computationally cheap, numerically stable, and parameter-efficient (only γ controls its shape).
✦Empirically validated on this task
  • The exact configuration used here (CUMUL features + RBF SVM) was published in the Panchenko et al. NDSS 2016 paper and achieved state-of-the-art accuracy at the time.
  • Multiple subsequent reproducibility studies confirmed >90% accuracy in closed-world settings with 100 sites, which this implementation targets.
✦Deterministic and reproducible
  • Given fixed training data and hyperparameters, SVM produces an identical model every run. There is no random initialisation or stochastic gradient descent. Critical for scientific reproducibility of fingerprinting experiments.
  • Stored .pkl artefacts allow exact model reconstruction from any training run.
✦Interpretable support vectors
  • model.support_vectors_ contains the actual training PCAP vectors closest to the decision boundary — the "hardest" examples. These can be inspected to understand what makes websites hard to distinguish.
  • model.n_support_ per class shows which websites require more support vectors (more complex traffic patterns), pointing to sites that are more difficult to fingerprint.
✦Calibrated probability output
  • probability=True enables Platt scaling, producing well-calibrated probability estimates per class. Used for ROC curves, top-5 accuracy, confidence thresholding in open-world mode.
  • The _score_matrix() fallback chain ensures scores are always available regardless of backend.
✦ThunderSVM GPU backend
  • The _resolve_svm_backend() function can transparently switch to ThunderSVM — a GPU-accelerated SVM that provides 10–100× speedup over sklearn's libsvm on large datasets.
  • Falls back gracefully to sklearn when ThunderSVM is not installed, requiring zero code changes.
9Shortcomings & Limitations
✗Quadratic scaling with training size
  • SVM training complexity is approximately O(N²) to O(N³) in the number of training samples N. For 100 sites × 50 instances = 5,000 samples, this is manageable. But scaling to 500 sites × 50 = 25,000 samples causes a ~25× slowdown.
  • GridSearchCV with 490 fits × 25,000 samples becomes impractically slow (hours) without the ThunderSVM GPU backend.
✗Memory-intensive at inference
  • Prediction requires computing kernel values between the test vector and all support vectors. With 100 classes and many support vectors per class, svm_model.pkl can grow to 100–500 MB.
  • A deep learning model (var-CNN) compresses the same discriminative information into fixed-size weight matrices, making inference faster and the model smaller.
✗Closed-world assumption
  • The SVM trained here assumes any incoming traffic must be one of the 100 monitored sites. In the real open-world scenario (the Tor network), most traffic is from the 400+ background sites not in the training set.
  • SVM does not natively produce an "unknown class" output. Thresholding predict_proba() at ALERT_THRESHOLD=0.60 is a workaround but introduces FAR/FRR tradeoffs.
✗Manual feature engineering dependency
  • Performance is entirely dependent on CUMUL feature quality. If the cumulative curve representation fails to capture a distinguishing pattern (e.g. for sites with nearly identical total traffic volume), the SVM cannot overcome this — it has no mechanism to learn better representations.
  • Deep learning (var-CNN) learns features directly from raw sequences, bypassing this bottleneck.
✗Sensitivity to data quality
  • The IQR-based validation and MIN_PACKETS=500 threshold filter out bad captures, but borderline traces (e.g. incomplete page loads, CDN failures) that pass validation still add noise. SVM with hard-margin C values is sensitive to this noise near the boundary.
  • Website content changes over time: a model trained on today's bbc.com will see a different CUMUL curve in 6 months due to redesigns, new CDN configs, or changed ad trackers.
✗No incremental learning
  • Adding a new monitored site requires retraining the entire SVM from scratch. OvO creates new binary classifiers for every (new_site, existing_site) pair — for 100 existing sites, adding site 101 requires training 100 new binary SVMs.
  • Deep learning models can be fine-tuned on new classes without full retraining.
✗GridSearchCV is computationally expensive
  • 7 × 7 × 10 = 490 full SVM fits per training run. Each fit involves the kernel matrix computation O(N² × d) where d=104. For large N, this dominates wall-clock time.
  • There is no warm-starting: each grid point trains from scratch. Bayesian optimisation (e.g. BayesSearchCV) could find optimal params with ~10× fewer evaluations.
✗Adversarial vulnerability
  • An adversary aware of the CUMUL fingerprinting approach can use traffic morphing (adding dummy packets) or burst splitting to shift the cumulative curve, degrading SVM accuracy.
  • Deep learning models with attention mechanisms are somewhat more robust to these adversarial perturbations because they learn multiple redundant representations.

When to use SVM (this implementation)
Choose SVM when: (1) you have fewer than ~200 instances per site, (2) you need deterministic reproducible results, (3) you want to validate results against the original Panchenko et al. paper directly, (4) GPU is not available, or (5) you need model interpretability via support vector inspection.
When to use var-CNN
Choose var-CNN when: (1) you have >200 instances per site, (2) training speed matters less than inference speed, (3) you want a smaller deployable model, (4) you need to extend to open-world classification, or (5) you have GPU resources available.
11Summary & Key Takeaways

How the SVM fits into the CUMUL pipeline

The CUMUL website fingerprinting system captures raw TCP traffic from Tor-proxied website visits, converts each trace into a 104-dimensional feature vector (100 interpolated curve points + 4 global stats), normalises these vectors to [−1, 1], and then trains a multiclass RBF-kernel SVM to map feature vectors to website identities.

The SVM's role is to learn the decision boundaries between the 100 monitored websites in this 104-dimensional space. It does so by finding the maximum-margin hyperplane (extended to a non-linear boundary via the RBF kernel) that separates each pair of classes. GridSearchCV with StratifiedKFold cross-validation selects the optimal C ∈ [2¹¹, 2¹⁷] and γ ∈ [2⁻³, 2³] that generalise best to unseen traffic traces.
