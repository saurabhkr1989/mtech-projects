1What is var-CNN?

var-CNN (Variable-length CNN) is a 1D convolutional neural network designed specifically for website fingerprinting attacks, introduced by Bhat et al. (2019) as an extension to the work on deep learning for traffic analysis. Unlike the SVM classifier which requires pre-engineered CUMUL features, var-CNN operates directly on raw packet sequences — it learns its own feature representations automatically from the raw traffic data.

The core idea is to treat a network traffic trace as a time-series signal: a sequence of packets with direction, size, and inter-arrival timing information. Convolutional filters slide over this sequence to detect local patterns — a burst of incoming packets, a sequence of small ACKs followed by a large response, a characteristic upload-download rhythm — that distinguish one website from another.

Why "variable-length"?
Different website visits produce traces of different lengths (different number of packets). A CNN with fixed-size input would require truncation or padding to the same length for every trace. The "var" prefix refers to the architecture's ability to handle variable-length sequences through its use of Global Average Pooling (GAP) and Global Max Pooling (GMP), which reduce any-length feature maps to a fixed-size vector regardless of input sequence length.
Original paper: Bhat et al. (2019)

Introduced var-CNN as an improvement over earlier deep learning WFP classifiers (AWF, SDAE). Demonstrated that a relatively shallow CNN architecture with variable-length input handling could match or exceed SVM+CUMUL accuracy while being significantly faster at inference time. The key innovation was GAP+GMP concatenation instead of flattening.

This implementation

An enhanced variant with Swish activations (replacing ReLU for smoother gradients), LayerNormalization (instead of BatchNorm for small batch sizes), and a deeper feature extraction stack (4 conv blocks vs original 2). These changes improve performance on the small-data regime (50 instances/site) characteristic of this project.

2Input Representation — Raw Sequences

The most fundamental difference between var-CNN and the SVM is their input format. While the SVM receives a 104-dimensional engineered feature vector, var-CNN receives the raw packet trace as a 2D matrix.

The 2000 × 3 input matrix
Channel Index What it encodes Value range Why it matters
Direction [:, 0] +1 for incoming packets (server→client), −1 for outgoing (client→server) {−1, +1} Encodes the direction rhythm — the sequence of uploads and downloads that characterises a site's loading pattern
Size [:, 1] Packet payload size in bytes, normalised by scale_factor [0, 1] after scaling Captures the size distribution — sites with many small requests vs few large transfers have distinct size channels
Inter-arrival time [:, 2] Time delta between consecutive packets, normalised [0, 1] after scaling Encodes timing rhythm — server think-time, CDN response latency, browser pipeline behaviour
Sequence length: MAX_TRACE_PACKETS = 2000
Truncation and zero-padding
Traces are truncated to the first 2000 packets if longer, and zero-padded if shorter. The scale_factor is computed from the 95th percentile of all packet sizes in the training set, normalising the size channel to [0,1]. This same scale_factor is stored in metadata.json and applied identically at test time — critical for consistent normalisation.
Input tensor shape X_train shape: (N_samples, 2000, 3) ← N_samples = sites × instances, e.g. 100 × 40 = 4000 for 40 train instances/site X_test shape: (M_samples, 2000, 3) ← each sample is a single PCAP file → 2000 time steps × 3 channels Compared to SVM input: (N_samples, 104) — 19× fewer features ← but var-CNN's input contains more raw information before compression
Why 2000 packets specifically?
The config parameter MAX_TRACE_PACKETS = 2000 is the standard used in the WFP literature (AWF, DF, var-CNN papers). Empirically, the first 2000 packets of a web page load contain the majority of the fingerprinting information — most of the distinguishing traffic happens in the initial burst phase. Packets beyond 2000 are often retransmissions, keep-alive signals, and background analytics that add noise rather than signal.

Layer-by-layer explanation
Layer Parameters What it learns Why this choice
Conv1D (k=7, 64f) 64 filters, kernel=7, padding=same, activation=Swish Low-level temporal patterns across 7 consecutive packets: short bursts, request-response pairs, ACK patterns Large kernel (7) captures local packet-level interactions without being too localised. First layer needs wide receptive field to see packet bursts.
LayerNormalization Normalises across feature dimension (not batch) Stabilises activations after each conv layer Chosen over BatchNorm because batch_size=8 is too small for reliable batch statistics. LayerNorm operates independently per sample, stable at any batch size.
MaxPooling1D (pool=2) Halves the sequence length Retains the strongest activation within each 2-step window (dominant pattern, not average) Reduces computational cost and creates translation invariance: a burst pattern shifted by 1 packet still fires the same filter.
Conv Block 1 (k=5, 96f × 2) Two stacked Conv1D layers before pooling Mid-level patterns: HTTP request sequences, TLS handshake structure, CDN response patterns Double-conv before pooling (VGG-style) increases representational depth before spatial reduction.
Conv Block 2 (k=3, 128f × 2) Small kernel as sequence gets shorter High-level patterns: resource loading order, page structure (header → content → ads) Kernel shrinks to 3 because after two MaxPool halvings, the sequence is already compressed; wide kernels would over-span the remaining signal.
Final Conv1D (k=3, 192f) Deepest conv layer, no pool Most abstract traffic fingerprint features at full 192-channel depth No pooling here — the sequence is already at 250 steps; dual global pooling handles the final aggregation more informatively than another MaxPool.
GAP + GMP → Concat GlobalAveragePooling1D + GlobalMaxPooling1D, concatenated to (384,) GAP: average traffic pattern over the entire trace. GMP: most distinctive single-point pattern in the trace This is the key var-CNN innovation. GAP captures global structure; GMP captures the single most distinctive moment. Together they provide richer features than either alone.
Dense 256 → Dense 128 Fully connected layers with Swish activation and Dropout Non-linear combinations of the pooled features for final classification Two-layer head provides sufficient capacity without excessive parameters. Dropout rates decrease (15% → 10%) toward the output to avoid excessive regularisation at the classification stage.
Dense N_classes + Softmax One neuron per monitored website, softmax activation Converts logits to probability distribution over classes Softmax ensures probabilities sum to 1; the argmax gives the predicted class; the full distribution gives confidence scores for ROC curves and open-world thresholding.
Swish activation f(x) = x · σ(x) Smooth non-linearity replacing ReLU throughout Swish outperforms ReLU on deep networks empirically. Unlike ReLU it is smooth and non-monotonic, providing better gradient flow during backpropagation with small batch sizes.
Debug overfit mode (sanity check architecture)
VARCNN_DEBUG_OVERFIT = True → simplified architecture
When config.VARCNN_DEBUG_OVERFIT = True, the full Conv1D stack is replaced with a simple Flatten → Dense(1024) → Dense(512) → Dense(256) → Softmax. This is a deliberate sanity check: if the simplified architecture cannot even overfit the training data, it indicates a data preprocessing bug rather than a model capacity issue. Used during development to verify sequence extraction correctness.
4Training Configuration & Strategies
Optimiser: Adam
Adam with learning rate 5×10⁻⁴
Adam (Adaptive Moment Estimation) maintains per-parameter learning rates adjusted by running estimates of first and second moments of gradients. VARCNN_LEARNING_RATE = 5e-4 is faster than the standard 3×10⁻⁴ to compensate for the very small dataset (50 instances/site) — slower learning would not converge within 120 epochs. The ReduceLROnPlateau callback halves the learning rate after 2 epochs without validation loss improvement, with a floor of 1×10⁻⁵.
Loss function: Sparse Categorical Crossentropy L = − (1/N) Σᵢ log( p(yᵢ | xᵢ) ) ← where p(yᵢ | xᵢ) is the softmax probability assigned to the true class ← "sparse" means integer labels are accepted directly (no one-hot encoding needed)

Splits training data into fit set (80%) and validation set (20%) using sklearn train_test_split with stratify=y. Validation set is used by EarlyStopping and ReduceLROnPlateau callbacks — it is distinct from the held-out test set.

Runs up to 120 epochs. EarlyStopping monitors val_accuracy with patience=4 and restores best weights. ReduceLROnPlateau halves LR after 2 non-improving epochs. Class weights compensate for imbalanced capture counts per site.

Predictions are raw softmax probabilities (N, N_classes). np.argmax(axis=1) gives predicted class indices. le.inverse_transform() maps indices back to string site labels. Accuracy computed via sklearn accuracy_score.

Model saved in Keras native format (not pickle). Training history (loss, val_loss, accuracy, val_accuracy per epoch) saved to history.json for learning curve visualisation. Scale_factor persisted in metadata for test-time use.
6Strengths of var-CNN for Website Fingerprinting
✦ No manual feature engineering
  • The Conv1D filters learn to detect whatever packet patterns distinguish websites best. There is no assumption that cumulative curves are the optimal representation.
  • If a site's distinguishing feature is a timing pattern rather than a size pattern, the network can learn to weight the inter-arrival channel accordingly.
✦ Fixed-size inference regardless of training set
  • Once trained, prediction is a fixed forward pass through the network: O(1) in the number of training examples. SVM prediction scales with support vector count.
  • Adding 10,000 more training examples does not slow down inference at all — the model weights have fixed size.
✦ Richer information from raw input
  • The (2000, 3) input contains all timing, direction, and size information from the first 2000 packets — far more raw information than the 104-dim CUMUL summary.
  • The CNN decides which aspects of this information are discriminative; CUMUL pre-decides for you.
✦ Scale well to larger datasets
  • Training time grows roughly linearly with dataset size (not quadratically like SVM). Adding more sites or more instances per site incurs manageable cost.
  • With enough data (200+ instances/site, 200+ sites), CNNs typically outperform SVMs significantly.
✦ Compact deployable model
  • The trained varcnn_model.keras file contains fixed weight matrices — typically 5–20 MB regardless of training set size.
  • SVM's svm_model.pkl grows with the number of support vectors, potentially reaching 100–500 MB for 100 classes.
✦ Multi-GPU training support
  • tf.distribute.MirroredStrategy transparently distributes training across all available GPUs. Linear speedup with GPU count.
  • SVM has no native multi-GPU support (ThunderSVM is single-GPU only).
✦ Natural open-world extension
  • Adding an "unknown" class to the softmax output is natural. Confidence thresholding on the maximum softmax probability provides a principled open-world detector.
  • The system already uses ALERT_THRESHOLD = 0.60 for open-world mode.
✦ Transfer learning potential
  • The convolutional feature extractor (everything before the Dense head) can be fine-tuned on new sites or new network conditions, rather than retraining from scratch.
  • Pre-trained weights can serve as a strong initialisation for new deployment scenarios.
7Shortcomings & Limitations
✗ Data-hungry — 50 instances/site is too few
  • The current project targets 50 instances per monitored site. This is barely sufficient for a CNN to learn robust convolutional filters. With 80/20 train/val split and 50 instances, the model trains on only 40 samples per site — critically low for a 100-class problem.
  • SVM with kernel methods achieves near-optimal boundaries with as few as 20–30 examples per class. CNNs typically require 100–500 per class.
✗ Non-deterministic — stochastic results
  • Random weight initialisation, batch shuffling, and EarlyStopping epoch selection all introduce randomness. Two training runs with identical data produce different models.
  • For a scientific reproducibility study (replicating Panchenko et al.), this is a significant disadvantage over the deterministic SVM.
✗ TensorFlow dependency — heavy and fragile
  • TensorFlow ≥2.16 requires careful environment setup. GPU support on Windows requires specific CUDA/cuDNN versions. Training without GPU is very slow (hours for 120 epochs × 500 steps/epoch).
  • The lazy-import pattern is used precisely because TF startup costs ~2 s and ~1 GB RAM even for CPU-only use.
✗ Overfitting risk on small dataset
  • The handover.md notes an observed gap: "18.4% CV accuracy vs 81% training accuracy (significant overfit)". With 50 instances/site and 100 classes, the model has millions of parameters relative to the ~4000 training samples — a severe over-parameterisation.
  • Reducing VARCNN_DROPOUT_SCALE = 0.1 mitigates this but also reduces regularisation on an already low-sample dataset.
✗ Hyperparameter sensitivity
  • Learning rate, dropout scale, batch size, and number of epochs interact in complex ways. A learning rate 2× too high causes divergence; 2× too low means 120 epochs aren't enough. SVM's hyperparameters (C, γ) are searched exhaustively; CNN's are tuned manually.
  • There is no GridSearchCV equivalent for CNNs in this project — the hyperparameters are fixed in config.py.
✗ Padding noise in input sequences
  • Traces shorter than 2000 packets are zero-padded. The network must learn to ignore trailing zeros, which are meaningless. Despite the model theoretically being able to learn this, zero regions in the input contribute noise to pooling operations.
  • Masking layers (Keras Masking layer) are not used in the current implementation, meaning all 2000 time steps are treated equally.
✗ No cross-validation scoring
  • SVM training produces a cross-validated accuracy score (cv_mean_accuracy ± cv_std) from cross_val_score(), providing a reliable generalisation estimate. var-CNN uses a single train/validation split — the val_accuracy is more sensitive to the random split.
  • K-fold CV for deep learning is computationally impractical here (it would require K full training runs).
✗ Opaque feature representation
  • The Conv1D filters are not directly interpretable. It is not possible to say "this filter detects CDN requests" — the representations are distributed across hundreds of filter activations.
  • SVM support vectors are actual training PCAP traces that can be inspected and understood.
8Where var-CNN Fails Specifically vs SVM — In This Project

This section addresses the most important question: given that both classifiers are implemented, why does var-CNN produce worse results than SVM in the current project configuration? The handover document explicitly notes this with the observation of 18.4% CV vs 81% training accuracy in var-CNN.

Root cause diagnosis: the 50 instances/site bottleneck

The fundamental reason var-CNN fails here is not architectural — it is a data starvation problem. The CNN is trained with approximately 40 instances per site (80% of 50). With 100 classes, this means the model must learn discriminative Conv1D filters from a training set of just 4,000 samples across a 6,000,000-dimensional raw input space. The SVM operates in 104-dimensional pre-compressed space, where 4,000 samples provides excellent coverage.

Failure mode Why SVM doesn't have this problem Evidence in codebase
Overfitting (81% train, 18% CV) SVM's margin maximisation explicitly optimises generalisation. With RBF kernel and large C, it creates tight but well-regularised boundaries. CV accuracy tracks training accuracy closely. handover.md: "18.4% CV accuracy vs 81% training accuracy (significant overfit)"
Under-trained convolutional filters SVM doesn't learn filters — it relies on CUMUL to pre-extract the signal. CUMUL is a mathematically principled representation that works with any sample count. 40 train samples per class × 3 channels × 2000 time steps = filters see too few examples of each class to generalise
EarlyStopping fires too early SVM either converges to optimal or doesn't — there is no "early stopping epoch" concept. The optimal solution is unique and always found (given the convex objective). patience=4 means the model stops after seeing val_accuracy plateau for 4 epochs — likely around epoch 15–25, well before the model has learned robust representations
Batch size 8 is too small for stable gradient estimates SVM uses the entire training set in each optimisation step — no batch variance. The optimal hyperplane is found exactly, not approximated by noisy mini-batch gradients. VARCNN_BATCH_SIZE = 8 means each gradient step sees only 8 of 4000 samples — high variance estimates, slow convergence
Validation split reduces already tiny training set SVM is cross-validated internally by GridSearchCV, which uses all training data across folds — every sample contributes to every fold's training set at some point. 20% validation split → 32 samples/site for fit, 8 for validation. This is a critically small split.
No CV score — single split evaluation is unreliable SVM produces cv_mean ± cv_std across 10 stratified folds — a statistically reliable estimate. The stochastic val split of var-CNN may accidentally be easy or hard. var-CNN metadata only stores train_accuracy and test_accuracy — no fold-averaged score
DROPOUT_SCALE=0.1 disables regularisation SVM's regularisation (C parameter) is already tuned via GridSearchCV to the optimal value. Reducing it would explicitly reduce the grid search range. Effective dropout rates: 0.5%, 1%, 1.5% — essentially no dropout. The model is unregularised and memorises training traces.
When would var-CNN surpass SVM in this project?
If the dataset were expanded to 200+ instances per monitored site (requiring ~4× more collection time), var-CNN would become competitive. At 500+ instances per site, var-CNN would likely outperform SVM, as the Conv1D filters would have sufficient examples to learn generalised traffic patterns that go beyond what the CUMUL representation captures. The infrastructure for this is already in place — only the data volume is the bottleneck.
9Why Not k-Nearest Neighbours (k-NN)?

k-NN was the dominant classifier in early website fingerprinting research (Herrmann et al. 2009, Panchenko et al. 2011) before the SVM era. It is instructive to understand exactly why it was not chosen for this implementation.

k-NN: How it would work here
Not suitable

Given a test traffic trace's 104-dim CUMUL vector, find the k training traces with smallest Euclidean distance. Assign the majority class among those k neighbours.

k-NN on raw sequences
Impractical

Computing Euclidean or DTW distance between 2000×3 sequences for every test-training pair. At 5000 training samples, each test prediction requires 5000 distance computations — O(N × L) where L=6000.

ProblemDetailHow SVM/CNN solves it
O(N) inference Every prediction requires comparing to ALL 5,000 training vectors. For a real-time Tor exit node monitor making thousands of predictions per minute, this is prohibitively slow. SVM: O(N_sv × d) where N_sv ≪ N. CNN: O(1) fixed forward pass.
O(N × d) memory The entire training set must be held in memory for inference. At 5000 samples × 104 features = 520K floats — manageable now but scales linearly. SVM stores only support vectors. CNN stores only weight matrices.
Curse of dimensionality In 104-dimensional space, Euclidean distance becomes increasingly meaningless — all points become approximately equidistant ("concentration of measure"). k-NN relies on meaningful distance geometry. SVM's kernel explicitly addresses this. CNN learns a discriminative low-dim embedding.
k hyperparameter sensitivity k=1 overfits. k=N underfits. Optimal k depends heavily on class density and varies per class. Finding it requires cross-validation over many k values. SVM has only 2 hyperparameters with well-understood effects. CNN's are tunable via callbacks.
No natural probability output k-NN "probability" = fraction of k neighbours in each class — a very coarse estimate, especially for small k. Poor for ROC curves and open-world thresholding. SVM: Platt scaling. CNN: softmax probabilities directly.
No feature learning k-NN in raw packet space gives meaningless distances. k-NN with CUMUL features is slightly better but still assumes the Euclidean metric is appropriate for fingerprint comparison. CNN learns its own metric implicitly through its feature representation.
Historically superseded Panchenko et al. (2016) — the exact paper this project implements — explicitly showed that SVM+CUMUL outperforms k-NN+CUMUL by a large margin across all dataset sizes tested. SVM chosen as the paper's primary result. var-CNN as the more modern extension.
10Why Not Triplet CNN?

Triplet networks have been used in advanced WFP research (Oh et al. 2019, Rimmer et al. 2018 "Automated Website Fingerprinting through Deep Learning") and offer interesting theoretical properties. Understanding why they were not chosen illuminates the design space of the field.

What a Triplet CNN is
Triplet loss learning: (anchor, positive, negative)
A Triplet CNN is a metric learning approach. Rather than directly classifying into N classes, it trains a CNN to produce an embedding — a fixed-size vector in a learned metric space — such that:
  • Same class → close embeddings: two traces from bbc.com should map to nearby points in embedding space
  • Different class → far embeddings: a trace from bbc.com and one from cnn.com should be far apart
Training uses triplets (anchor, positive, negative): anchor and positive are same-class traces; negative is a different-class trace. The loss pushes anchor closer to positive and further from negative.
Triplet loss function L = max(0, ‖f(a) − f(p)‖² − ‖f(a) − f(n)‖² + margin) ← f(·) = CNN embedding function ← a = anchor trace, p = positive (same site), n = negative (different site) ← margin: minimum distance separation required between classes
Consideration Triplet CNN Why var-CNN was chosen instead
Data required Triplet mining requires enough samples per class to find hard negatives. With 50 instances/site, triplet mining produces very few informative triplets (easy triplets dominate and contribute zero gradient). var-CNN's cross-entropy loss is effective with as few as 10–20 samples per class. No triplet mining needed.
Training complexity Must implement online/offline triplet mining strategy (random, semi-hard, or hard). Semi-hard mining requires careful distance monitoring during training. Much more engineering overhead. var-CNN trains with standard categorical cross-entropy — the simplest, most robust loss. No special mining needed.
Adding new classes Major advantage: adding a new website requires no retraining. Just capture a few traces and add them as reference points in embedding space (few-shot / open-set recognition). var-CNN requires full retraining to add new classes. But so does SVM — and SVM is already the baseline here.
Open-world performance Naturally handles open-world: unmonitored sites produce embeddings far from all monitored site clusters. Distance to nearest cluster is a reliable "unknown" detector. var-CNN handles open-world via softmax thresholding — less principled but sufficient for current scope.
Closed-world accuracy (50 inst/site) Typically lower than cross-entropy CNN in the closed-world regime when data is sparse. The embedding space is harder to train correctly without many intra-class examples. var-CNN's cross-entropy directly optimises the classification objective. More efficient use of limited data.
Implementation complexity Requires: triplet sampler, embedding extraction, nearest-centroid/k-NN classifier on embeddings, separate distance metric tuning. 3× more code than a standard CNN classifier. var-CNN is a standard Keras model trained end-to-end. Minimal implementation complexity. Easier to debug and maintain.
Existing literature baseline Not directly comparable to the Panchenko et al. (2016) SVM+CUMUL baseline which this project implements. Introduces architectural differences that obscure the CUMUL contribution. var-CNN was explicitly designed as an extension to the same-data WFP problem, making direct comparison fair.
When would Triplet CNN be the right choice?
If the project needed to: (1) fingerprint thousands of websites with only 5–10 examples each (few-shot), (2) deploy a system where new monitored sites are added frequently without full retraining, (3) operate in open-world mode as the primary use case, or (4) transfer fingerprinting models between different network environments (domain adaptation). None of these are the current project's primary goal.
11Why var-CNN — The Deliberate Design Choice

Given that var-CNN underperforms SVM in the current data-sparse configuration, why is it included at all? The answer is forward-looking and grounded in the project's longer-term goals.

var-CNN — Chosen
Included

Direct literature comparison (Bhat et al. 2019). Same interface as SVM (train_from_selection / test_from_selection). Operates on raw sequences — no CUMUL needed. Will outperform SVM when dataset reaches 200+ instances/site. Already implemented and tested.

k-NN — Rejected
Excluded

O(N) inference, curse of dimensionality in 104-dim space, historically inferior to SVM+CUMUL per the Panchenko paper, no natural probability output for open-world detection.

Triplet CNN — Excluded
Future work

Requires 5× more data per class for effective triplet mining, significantly higher implementation complexity, not directly comparable to the SVM baseline. Excellent future direction for few-shot and open-world WFP.

Random Forest — Excluded
Excluded

Strong competitor on tabular features, but operates in the same CUMUL-feature space as SVM — would not add a new data modality. Inferior to RBF-SVM empirically in the traffic fingerprinting literature.

The unified interface — why this matters
train.py and test.py call both classifiers identically
Both svm_model.train_from_selection() and varcnn.model.train_from_selection() have identical call signatures and return identical result dicts (y_true, y_pred, y_score, class_labels, accuracy, ...). graphs.py:generate_graphs() accepts either result transparently. This means once the dataset grows to 200+ instances per site, switching from SVM to var-CNN requires changing exactly one line in train.py. The system is designed for this migration.
12Summary & Key Takeaways

var-CNN in the CUMUL system — current state

var-CNN is a 1D convolutional network taking raw (2000, 3) packet sequences as input. It learns its own traffic fingerprint features through 4 convolutional blocks, dual GAP+GMP pooling, and a 2-layer classification head. It is trained with Adam optimiser, sparse categorical crossentropy loss, EarlyStopping, ReduceLROnPlateau, and class weight balancing.

In the current project configuration (50 instances/site, 100 classes), var-CNN underperforms SVM+CUMUL due to data starvation — the CNN cannot learn generalised convolutional filters from only 40 training traces per class. SVM with pre-engineered CUMUL features is more data-efficient and achieves better cross-validated accuracy with the current dataset size.

var-CNN is included because: (1) it provides a direct comparison with the Bhat et al. (2019) literature, (2) it will surpass SVM when the dataset reaches 200+ instances/site, and (3) the unified interface allows zero-code-change switching between classifiers when the data volume milestone is reached.
