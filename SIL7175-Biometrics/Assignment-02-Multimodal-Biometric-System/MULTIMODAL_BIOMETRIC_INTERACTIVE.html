🎯 System Overview

Why Multimodal Biometric Systems?

Unimodal biometric systems that rely on a single trait suffer from critical limitations:

❌ Problems with Single Modality:

  • Non-Universality: Not all users can provide all modalities reliably
  • Noise Susceptibility: Single trait vulnerable to sensor errors
  • Spoofing Vulnerability: Face spoofed by photos, iris by contacts
  • Single Point of Failure: System completely fails if one modality fails

✅ Solution: Multimodal Fusion

  • Physiological Traits: Face & Iris (structure-based)
  • Behavioral Traits: Signature (action-based)
  • Complementary Information: Different vulnerability vectors
  • Redundancy: System robust if one modality fails

Cross-Validation Strategy

Challenge: Different modalities have different sample counts
Face: 5-20 images per user
Iris: 4-10 samples per user
Signature: 15-30 samples per user
Solution: 5-Fold Cross-Validation with Minimum Samples
1. For each user, find N = min(n_face, n_iris, n_signature)
2. Create N distinct Chimeric Tuples pairing N samples from each modality
3. Stratified 5-fold split on these N tuples
4. Average metrics across 5 folds

Example: User_42

Available Samples: ├─ Face images: 8 ├─ Iris samples: 6 └─ Signatures: 25 Minimum N = 6 Create 6 Chimeric Tuples: ├─ Tuple_1: (Face_1, Iris_1, Sig_1) ├─ Tuple_2: (Face_2, Iris_2, Sig_2) ├─ Tuple_3: (Face_3, Iris_3, Sig_3) ├─ Tuple_4: (Face_4, Iris_4, Sig_4) ├─ Tuple_5: (Face_5, Iris_5, Sig_5) └─ Tuple_6: (Face_6, Iris_6, Sig_6) 5-Fold Split: ├─ Fold_1: Test={Tuple_1}, Train={2,3,4,5,6} ├─ Fold_2: Test={Tuple_2}, Train={1,3,4,5,6} ├─ Fold_3: Test={Tuple_3}, Train={1,2,4,5,6} ├─ Fold_4: Test={Tuple_4}, Train={1,2,3,5,6} └─ Fold_5: Test={Tuples_5,6}, Train={1,2,3,4}

👤 Face Modality - Complete Pipeline

Step 1: Preprocessing

Raw Face Image ↓ [Landmark Detection - Dlib 68 points] 68 Facial Landmarks (eyes, nose, mouth, jawline) ↓ [ROI Extraction - 15 overlapping 30×30 patches] 15 Enhanced Patches ↓ [Histogram Equalization] Contrast Enhanced Patches ↓ [Mean-Variance Normalization] Standardized Patches (μ=0, σ=1)

Why Preprocessing Matters?

Details: Histogram Equalization +
PROBLEM: Input histogram concentrated in narrow range [100-150] Not utilizing full [0-255] intensity range Hard to extract consistent features SOLUTION - Histogram Equalization: Map pixels through CDF (Cumulative Distribution Function) I_new = round(CDF[I_old] × 255) EFFECT: ✓ Full dynamic range utilized ✓ Contrast enhanced ✓ Illumination invariant features enabled
Details: Mean-Variance Normalization +
FORMULA: I_normalized = (I - μ) / σ WHERE: μ = mean of patch intensities σ = standard deviation EFFECT: ✓ Zero mean: Center data at 0 ✓ Unit variance: Scale to consistent range ✓ Standardization: Same distribution across patches → Result: Intensity scale invariant

Step 2: Feature Extraction - Pipeline A (ULBP)

15 Preprocessed 30×30 Patches ↓ [Divide into 10×10 blocks] 9 blocks per patch ↓ [ULBP Computation: P=8, R=1] Compare 8 neighbors to center pixel ↓ [Create histogram] 59-bin histogram per block ↓ [Concatenation] 15 patches × 59 bins = 885-dimensional vector
Details: ULBP (Uniform Local Binary Patterns) +
ALGORITHM: For each center pixel (excluding borders): 1. Get center value: c = I[i,j] 2. Compare 8 neighbors (P=8, radius R=1): neighbors = [I[i-1,j-1], I[i-1,j], I[i-1,j+1], I[i,j-1], I[i,j+1], I[i+1,j-1], I[i+1,j], I[i+1,j+1]] 3. Threshold: b_k = (neighbor_k >= c) ? 1 : 0 4. Binary pattern: b = [b0, b1, ..., b7] 5. Rotation-invariant mapping: Find minimum rotation 6. Uniformity constraint: Only 59 uniform patterns 7. Histogram: Count occurrences PROPERTIES: ✓ Rotation invariant: Same texture at different angles ✓ Illumination robust: Uses comparison, not absolute values ✓ Low-dimensional: 59 bins vs thousands of pixels ✓ No learning: Deterministic, fast computation

Step 3: Feature Extraction - Pipeline B (SE-AlexNet)

Raw Face Image (224×224×3) ↓ [Conv Layer 1-5] Hierarchical feature extraction ↓ [Squeeze-Excitation Block] ← ATTENTION MECHANISM Learn which channels are important ↓ [Fully Connected Layers] FC1: Feature extraction layer ↓ [FC2 Layer Output] 4,096-dimensional feature vector
Details: Squeeze-Excitation (SE) Attention Mechanism +
SE BLOCK OPERATIONS: 1. SQUEEZE (Global Average Pooling): Goal: Compress spatial dims (H×W) to channel descriptor zc = (1/(H×W)) × Σ Σ Fc(i,j) WHERE: - Fc(i,j): Intensity at position (i,j) of channel c - zc: Single value per channel INPUT: 256 × 7×7 feature map OUTPUT: 256-dimensional channel descriptor 2. EXCITATION (Adaptive Re-weighting): Goal: Learn which channels are identity-relevant h = ReLU(W1 · z) [reduction: 256→16] s = σ(W2 · h) [expansion: 16→256 + sigmoid] WHERE: - σ = sigmoid (outputs [0,1]) - s = attention weights for each channel OUTPUT: 256 attention weights ∈ [0,1] 3. SCALE (Re-weight): F'c = sc ⊙ Fc [element-wise multiplication] High-importance channels: Amplified (s_c close to 1.0) Low-importance channels: Suppressed (s_c close to 0.0) OUTPUT: Re-weighted feature map WHY THIS WORKS: If eye texture is identity-relevant: → SE learns high s_c for eye channels → Those channels get amplified → Identity signal strengthened → Background/noise suppressed

Step 4: Verification - Binary SVM

For each of 100 enrolled users: Training: ├─ Positive class: Target user's face features ├─ Negative class: Random impostor faces (1:3 ratio) ├─ Kernel: RBF (non-linear boundaries) ├─ Class weight: 'balanced' (handles imbalance) └─ Output: Trained SVM model per user Verification: ├─ Extract test features (ULBP + Deep) ├─ Query user's SVM classifier ├─ Get score: f(x) = Σ αi·yi·K(xi,x) + b ├─ Apply threshold (usually 0) └─ Decision: Match (1) or No-Match (0)

👁️ Iris Modality - Complete Pipeline

Step 1: Iris Segmentation

Raw Eye Image (640×480) ↓ [Hough Circle Transform] Detect pupil (dark circle at center) Detect iris boundary (brighter circle) ↓ [Output] Segmented iris region (~120-150 pixel radius)

Step 2: Daugman Rubber Sheet Normalization

Circular Iris Image ↓ [Polar to Rectangular Transformation] Map (r,θ) in polar → (row,col) in rectangular ↓ [Output] 512×64 Normalized Iris Matrix (Columns: Angular direction | Rows: Radial direction)
Details: Daugman Mathematical Mapping +
PROBLEM SOLVED: - Different iris sizes: Pupil dilation varies - Iris rotation: Head tilt at different angles - Need standardized representation for comparison DAUGMAN SOLUTION: For each point (row, col) in normalized 512×64 space: 1. Radial mapping (rows → pupil to boundary): r_normalized = row / 64 [0 to 1] r_pixels = r_p + r_norm × (r_i - r_p) WHERE: - r_p = pupil radius (e.g., 50 pixels) - r_i = iris boundary radius (e.g., 120 pixels) - Result: [50, 120] pixels mapped to 64 rows 2. Angular mapping (cols → full circle): θ_normalized = col / 512 [0 to 512] θ = θ_norm × 2π [0 to 2π radians] Result: Full 360° mapped to 512 columns 3. Cartesian conversion: x = center_x + r_pixels × cos(θ) y = center_y + r_pixels × sin(θ) I_normalized[row, col] = I_original[y, x] EXAMPLE MAPPINGS: (row=0, col=0): r=50px (pupil edge), θ=0° (right) → Original: (370, 240) (row=32, col=256): r=85px (mid-iris), θ=180° (left) → Original: (235, 240) (row=64, col=512): r=120px (iris boundary), θ=360° (full rotation) → Original: (440, 240) BENEFITS: ✓ Invariant to iris size (handles pupil dilation) ✓ Handles rotation (circular mapping) ✓ Standardized 512×64 for all irises

Step 3: Strip Generation

512×64 Normalized Iris Matrix ↓ [Divide into overlapping strips] 10 horizontal strips (32×512 pixels each) 4-pixel overlap between consecutive strips ↓ [Enhancement per strip] Histogram Equalization (localized) ↓ [Output] 10 Enhanced Iris Texture Strips

Step 4: Feature Extraction - ULBP on Iris

For each of 10 iris strips: Block Division: ├─ 32×512 strip → 16×16 blocks ├─ Blocks: (512/16) × (32/16) = 32 × 2 = 64 blocks per strip └─ Total per iris: 10 strips × 64 blocks = 640 blocks ULBP Computation (P=8, R=1): ├─ For each block: Create 59-bin histogram ├─ Features per strip: 64 blocks × 59 bins = 3,776 dimensions └─ Total iris vector: 10 × 3,776 = 37,760 dimensions COMPARISON WITH FACE: Face ULBP: 15 patches × 59 = 885-dim (low noise) Iris ULBP: 10 strips × 64 blocks × 59 = 37,760-dim (detailed!) WHY IRIS FEATURES ARE MUCH HIGHER-DIM: Iris contains extremely fine texture details: ├─ Radial furrows: Deep grooves ├─ Crypts: Small pits ├─ Stromal fibers: Detailed patterns ├─ Capillaries: Fine blood vessels → High-dimensional features capture these micro-details

✍️ Signature Modality - Complete Pipeline

Why Signature is Different?

Physiological Traits (Face, Iris)

  • Affected by lighting conditions
  • Sensitive to camera angle/distance
  • Change with aging/expressions
  • Vulnerable to environmental noise

Behavioral Traits (Signature)

  • Invariant to capture conditions
  • Independent of illumination/angle
  • Consistent across lifetime (strokes stable)
  • Robust to environmental variations

Step 1: Preprocessing Pipeline

Grayscale Scanned Signature ↓ [Otsu's Binarization] Separate ink (foreground) from paper (background) ↓ [Inversion Check] Ensure ink=1, paper=0 ↓ [Center-of-Mass Calculation] Calculate signature center coordinates ↓ [Image Centering] Align to canvas center ↓ [Resizing] Fixed 170×242 pixels (nearest-neighbor) ↓ [Output] Binary signature with centered strokes
Details: Otsu's Binarization Algorithm +
GOAL: Find threshold T that separates ink from paper ALGORITHM: Compute between-class variance for each threshold: σ²_B(T) = ω₀(T) × ω₁(T) × [μ₀(T) - μ₁(T)]² WHERE: - ω₀(T) = proportion of pixels < T (background) - ω₁(T) = proportion of pixels ≥ T (foreground) - μ₀(T) = mean intensity of pixels < T - μ₁(T) = mean intensity of pixels ≥ T PROCESS: 1. Compute histogram of grayscale intensities 2. Try each possible threshold T ∈ [0,255] 3. Calculate σ²_B(T) for each 4. Find T that maximizes σ²_B 5. Result: Optimal threshold for binarization OUTPUT: Binary image where: ├─ Pixels < T → 0 (paper/background) └─ Pixels ≥ T → 1 (ink/foreground) ADVANTAGE: ✓ Automatic: No manual parameter tuning ✓ Robust: Works across different lighting conditions ✓ Optimal: Mathematically derived
Details: Center-of-Mass Calculation +
GOAL: Find geometric center of signature strokes CALCULATION: Column average (weighted by ink): cx = Σ Σ (j × I[i,j]) / Σ Σ I[i,j] Row average (weighted by ink): cy = Σ Σ (i × I[i,j]) / Σ Σ I[i,j] WHERE: - I[i,j] ∈ {0, 1} (binary image) - Only ink pixels (I=1) contribute to sums - j: column index - i: row index EXAMPLE: If 54 ink pixels total: Column positions: 1,2,3,4,5,6 (repeated 9 times) cx = Σ(1+2+3+4+5+6) × 9 / 54 = 21×9/54 = 3.5 Row positions: 1,2,3,4,5,6,7,8,9 (repeated 6 times) cy = Σ(1+2+3+4+5+6+7+8+9) × 6 / 54 = 45×6/54 = 5.0 RESULT: Signature center at (3.5, 5.0)

Step 2: Writer-Independent Feature Learning

Key Concept: Pre-train on DIFFERENT users to learn universal handwriting characteristics, then apply to target users.

Development Set (D)

Purpose: Train CNN to recognize general handwriting styles Users: 50-100 different users (NOT in target 100) Data: 10-20 signatures per user Task: Softmax classification (predict user identity) Output: Trained AlexNet_N with learned stroke topology filters

Exploitation Set (E)

Purpose: Apply learned features to target users Users: Target 100 users (never seen during training) Data: 15-30 signatures per user Task: Feature extraction (CNN frozen, weights fixed) Processing: 1. Pass signatures through trained CNN 2. Extract FC2 layer activations 3. Get 1024-dim feature vectors 4. Train SVM per user on these

Step 3: AlexNet_N Architecture

Binary 170×242 Signature Image ↓ CONV1: 32 filters (5×5) → BatchNorm + ReLU + MaxPool → 32×85×121 ↓ CONV2: 64 filters (5×5) → BatchNorm + ReLU + MaxPool → 64×42×60 ↓ CONV3: 128 filters (3×3) → BatchNorm + ReLU → 128×42×60 ↓ CONV4: 256 filters (3×3) → BatchNorm + ReLU → 256×42×60 ↓ CONV5: 256 filters (3×3) → BatchNorm + ReLU → 256×42×60 ↓ FLATTEN: 645,120 → 1D ↓ FC1: 645,120 → 1,024 → BatchNorm + ReLU ↓ FC2: 1,024 → 1,024 → BatchNorm + ReLU ← FEATURE EXTRACTION POINT ↓ FC3: 1,024 → |D| → Softmax (classification, only in development)
Details: Why Batch Normalization is CRITICAL for Signatures +
❌ Problem WITHOUT Batch Normalization:
Signature images: Sparse binary (mostly 0=paper, few 1=ink)
Early layers see highly imbalanced distributions
Activations become saturated (all 0 or all 1)
Gradients vanish: dL/dw → 0 (no learning!)
Result: Training FAILS to converge
✅ Solution: Batch Normalization
Applied after EVERY layer (conv and FC), BEFORE activation

For each mini-batch:
1. Compute batch mean: μ_B = (1/B) × Σ x_i
2. Compute batch variance: σ²_B = (1/B) × Σ (x_i - μ_B)²
3. Normalize: x̂_i = (x_i - μ_B) / √(σ²_B + ε)
4. Scale/shift: y_i = γ × x̂_i + β

Effects:
✓ Stabilizes internal covariate shift
✓ Normalizes to Gaussian (zero mean, unit variance)
✓ Allows higher learning rates
✓ Acts as regularizer
Result: AlexNet_N converges, achieves EER 0.012!

Phase 1: Development Set Training ├─ Train AlexNet_N on development users ├─ Learn universal handwriting topology └─ Save trained model weights Phase 2: Exploitation Set Feature Extraction ├─ Load trained model (weights FROZEN) ├─ Pass each exploitation set signature through frozen network ├─ Extract FC2 layer activations: 1,024-dimensional vector └─ Output: Feature vectors ready for SVM Phase 3: SVM Training Per User For each of 100 target users: ├─ Positive class: Target user's FC2 features (genuine) ├─ Negative class: Random impostor FC2 features ├─ Ratio: 1:3 positive:negative ├─ Kernel: RBF ├─ Class weight: 'balanced' └─ Output: Binary SVM classifier

🔀 Fusion Strategies & The Fusion Paradox

Approach 1: Feature-Level Fusion (Early Fusion)

5 Feature Vectors ├─ Face ULBP: 885-dim ├─ Face SE-AlexNet: 4,096-dim ├─ Iris ULBP: 37,760-dim (DOMINATES!) ├─ Iris SE-AlexNet: 4,096-dim └─ Signature AlexNet_N: 1,024-dim ↓ CONCATENATION: Stack all into single vector ↓ Fused Vector: 47,861 dimensions ↓ MASTER SVM: Train one SVM per user on concatenated vectors ↓ VERIFICATION: Single decision per user

Approach 2: Decision-Level Fusion (Late Fusion)

5 Binary Classifiers (Independent SVMs) ├─ Face ULBP SVM → Decision ∈ {0,1} ├─ Face SE-AlexNet SVM → Decision ∈ {0,1} ├─ Iris ULBP SVM → Decision ∈ {0,1} ├─ Iris SE-AlexNet SVM → Decision ∈ {0,1} └─ Signature AlexNet_N SVM → Decision ∈ {0,1} ↓ MAJORITY VOTING (3/5 required) ↓ D_final = 1 if Σ D_i ≥ 3, else 0 ↓ FINAL DECISION: Match or No-Match

⚠️ THE FUSION PARADOX EXPLAINED

Problem: Both fusion methods UNDERPERFORM signature alone!

Signature alone: 98.83%
Feature fusion: 86.80% ← 12% WORSE!
Decision fusion: 91.00% ← 8% WORSE!

Root Cause 1: Feature Contamination (Feature-Level Fusion)

PROBLEM: Dimensionality breakdown: ├─ Iris ULBP: 37,760 dims (79.1% of total!) ◄─ DOMINATES ├─ Face features: 4,981 dims (10.5%) └─ Signature: 1,024 dims (2.1%) ◄─ OVERWHELMED High-variance features dominate optimization: ├─ Iris ULBP: Highly variable, noisy (79% weight) ├─ Face features: High variance in RGB (10% weight) └─ Signature: Clean, precise signal (2% weight) SVM Optimization: Minimize: ||w||² + C × Σ ξ_i Gradient descent naturally flows toward: ├─ High-variance dimensions (iris) ├─ Noise-filled spaces └─ AWAY from signature signal RESULT: Signature's excellent discriminative power (EER 0.012) is DILUTED by iris noise (37,760 meaningless dimensions) Mathematical effect: - Signature contributes 2% to feature space - But needs 100% influence to maintain 98.83% accuracy - Instead: 79% iris noise suppresses signature ANALOGY: Mixing 1 cup of pure honey with 49 cups of bitter water = Diluted product (86.80%) worse than original honey (98.83%)

Root Cause 2: Decision Bottleneck (Decision-Level Fusion)

PROBLEM: Voting Rule: 3 out of 5 must agree Modality Accuracies (Dataset 1): ├─ Signature: 98.83% (best) ├─ Face Deep: 96.04% ├─ Iris Deep: 85.77% ├─ Iris ULBP: 86.10% └─ Face ULBP: 77.83% (worst) Scenario: Genuine User Verification If signature is CORRECT but only 2 others agree: Vote: [1, 0, 1, 1, 0] = 3 votes → PASS ✓ (Signature's YES + 2 others = consensus) But if signature is CORRECT but only 1 other agrees: Vote: [1, 0, 0, 1, 0] = 2 votes → FAIL ✗ (Signature's YES + only 1 other ≠ majority!) WORST CASE: Signature: YES (correct) Other 4 modalities: NO (all wrong) Vote: [1, 0, 0, 0, 0] = 1 vote → FAIL ✗ → False rejection! (genuine user rejected) MATHEMATICAL PENALTY: Accuracy with majority voting: = P(at least 3/5 correct) = P(exactly 3) + P(exactly 4) + P(exactly 5) This is LESS than individual best performer because worst performers drag down the ensemble Example calculation (if independent): P(all 5 correct) ≈ 0.985 × 0.96 × 0.858 × 0.861 × 0.778 ≈ 0.55 P(at least 3 correct) ≈ 0.75 (rough estimate) But signature alone = 98.83%! Majority voting loses signature's excellence

Why Naive Fusion Fails

NAIVE FUSION ASSUMPTION: "More modalities = More information = Better performance" REALITY: "More weak modalities = Bottleneck on strong modality" ENSEMBLE LEARNING SUCCESS (normal case): - Classifiers: 85%, 87%, 86% (all good quality) - Ensemble: 90% (improvement!) - Diverse AND accurate → Combined better THIS SYSTEM (failure case): - Signature: 98.83% (excellent) - Iris: 85.77% (good) - Face: 77.40% (poor in RGB) - Feature fusion: 86.80% (signature diluted) - Decision fusion: 91.00% (signature suppressed) KEY DIFFERENCE: Signature is TOO GOOD, others are TOO WEAK → Naive fusion averaging hurts not helps

Solutions: Better Fusion Strategies

Recommendation 1: Weighted Fusion
Instead of equal concatenation, use learned weights:
V_weighted = [1.0×V_sig || 0.3×V_iris || 0.1×V_face]
→ Signature dominates, others contribute moderately
→ Expected: >95% accuracy
Recommendation 2: Gated Fusion
Use signature decision, add others only when confident:
If signature confident (score >2σ): Use signature alone
Else: Use signature + iris confirmation
Avoid face in RGB unconstrained environments
→ Expected: Signature excellence + robustness
Recommendation 3: Hierarchical Fusion
Two-stage decision tree:
Stage 1: Signature votes → Strong decision?
Yes → Accept (98.83% confidence)
No → Stage 2: Add iris for confirmation
→ Leverage signature excellence, avoid bottleneck

Transformation Mathematics +
INPUT: Circular iris image ├─ Center: (xc, yc) = (320, 240) ├─ Pupil radius: r_p = 50 pixels ├─ Iris boundary: r_i = 120 pixels └─ Size: 640×480 DAUGMAN TRANSFORMATION: For each point (row, col) in normalized 512×64 space: 1. RADIAL MAPPING (row → radius): row_normalized = row / 64 [0 to 1] r_pixels = r_p + row_norm × (r_i - r_p) Examples: row=0 → r_norm=0.0 → r=50 (pupil edge) row=32 → r_norm=0.5 → r=85 (middle) row=64 → r_norm=1.0 → r=120 (boundary) 2. ANGULAR MAPPING (col → angle): col_normalized = col / 512 [0 to 512] θ = col_norm × 2π [0 to 2π radians] Examples: col=0 → θ=0° (3 o'clock, right) col=128 → θ=90° (12 o'clock, top) col=256 → θ=180° (9 o'clock, left) col=384 → θ=270° (6 o'clock, bottom) col=512 → θ=360° (full rotation) 3. CARTESIAN CONVERSION: x = xc + r_pixels × cos(θ) y = yc + r_pixels × sin(θ) I_normalized[row, col] = I_original[y, x] 4. EXAMPLE PIXEL MAPPINGS: Normalized (0, 0): r=50, θ=0° → x=320+50=370, y=240 Normalized (32, 256): r=85, θ=180° → x=320-85=235, y=240 Normalized (64, 512): r=120, θ=360°=0° → x=320+120=440, y=240 PROPERTIES: ✓ Invariant to iris size: Small iris: r_p=40, r_i=100 → Maps to same 512×64 Large iris: r_p=60, r_i=130 → Maps to same 512×64 ✓ Handles rotation: Iris rotated 90° → Shifted columns (can compensate) ✓ Standardized dimensions: All irises → 512×64 regardless of input size OUTPUT: 512×64 normalized iris matrix (ready for feature extraction)

Complete SE Block Computation +
INPUT: Feature Map F from Conv layer ├─ Dimensions: C × H × W ├─ Example: 256 × 7×7 (256 channels, 7×7 spatial) └─ Total values: 256 × 49 = 12,544 STEP 1: SQUEEZE (Global Average Pooling) Goal: Compress spatial dimensions, keep channel info For each channel c: zc = (1/(H×W)) × Σ Σ Fc(i,j) where: ├─ H=7, W=7 → 1/49 ├─ Σ: Sum over all spatial positions └─ Fc(i,j): Intensity at (i,j) in channel c Example (Channel 0): F_0 (7×7 feature map): 1.2, -0.3, 2.1, 0.5, -1.2, 0.9, 1.5 0.8, 1.5, 0.4, 1.8, 0.3, -0.1, 0.7 -0.5, 0.2, 1.3, 0.6, 1.1, 0.4,-0.2 0.9, 1.4, -0.7, 0.2, 0.5, 1.6, 0.8 1.2, 0.3, 0.9, 1.1, 0.7, 0.2, 1.4 0.6, -0.4, 1.5, 0.8, 0.9, 1.3, 0.5 1.1, 0.7, 0.3, 1.2, 0.4, 0.6, 1.0 Sum = 32.5 z_0 = 32.5 / 49 = 0.664 Repeat for all 256 channels: z = [0.664, -0.123, 0.891, ..., 0.234] Output z ∈ R^256 STEP 2: EXCITATION (Adaptive Re-weighting) Goal: Learn which channels matter for identity FC Layer 1 (Reduction): h = ReLU(W1 · z) Where: ├─ W1 ∈ R^(16×256) [reduction: 256→16] ├─ Matrix multiplication: W1·z ├─ ReLU activation: max(0, x) └─ Output: h ∈ R^16 Example: h[0] = ReLU(0.1×0.664 + 0.02×(-0.123) + ... + 0.08×0.234) = ReLU(0.4521) = 0.4521 FC Layer 2 (Expansion + Sigmoid): s = σ(W2 · h) Where: ├─ W2 ∈ R^(256×16) [expansion: 16→256] ├─ σ(x) = 1/(1+exp(-x)) [sigmoid, outputs [0,1]] └─ Output: s ∈ [0,1]^256 Example: s_pre[0] = W2[0,:] · h = 0.7451 (unbounded) s[0] = σ(0.7451) = 1/(1+exp(-0.7451)) = 0.678 Result: s = [0.678, 0.442, 0.891, ..., 0.234] (Attention weights for 256 channels) Interpretation: ├─ s[c] ≈ 1.0: Channel c is important for identity ├─ s[c] ≈ 0.5: Channel c is neutral └─ s[c] ≈ 0.0: Channel c is not important (noise) STEP 3: SCALE (Re-weight Feature Map) Goal: Apply learned importance to features For each channel c: F'_c = s_c ⊙ F_c where ⊙ is element-wise multiplication Example (Channel 0, s_0 = 0.678): Original F_0[0,0] = 1.2 Scaled F'_0[0,0] = 0.678 × 1.2 = 0.813 All values in channel 0 multiplied by 0.678 Example (Channel 100, s_100 = 0.123): All values in channel 100 multiplied by 0.123 (This channel is suppressed!) OUTPUT: Re-weighted Feature Map F' ∈ R^(256×7×7) ├─ Important channels: Amplified (×1.0 weights) ├─ Unimportant channels: Suppressed (×0.0 weights) └─ Identity-relevant features enhanced MATHEMATICAL EFFECT: SE block learns identity-specific importance → Downstream layers receive priority signal → Network focuses on identity features → Noise and artifacts suppressed

NIR vs RGB Physics: Why the Gap?

🔵 NIR (Near-Infrared) - Dataset 1

Light spectrum: 880-940 nm Properties: ├─ Penetrates skin ├─ Structural reflectance ├─ Skin pigment independent ├─ Shadow-free illumination └─ Uniform lighting Face Features Captured: ├─ Bone structure geometry ├─ Facial contours ├─ Eye sockets └─ Minimal skin tone variation SE-AlexNet Performance: ├─ Learns pure identity geometry ├─ Attention blocks identify bones ├─ Minimal noise └─ Result: 96.04% accuracy! Advantages: ✓ Clean signal ✓ High quality features ✓ Deep learning excels

🔴 RGB (Visible Light) - Dataset 2

Light spectrum: 400-700 nm Properties: ├─ Surface reflectance ├─ Skin tone dependent ├─ Complex ambient shadows ├─ Pose-dependent lighting └─ Background clutter Face Features Captured: ├─ Shadows (→ fake identity) ├─ Highlights (→ fake identity) ├─ Skin color variation ├─ Pose artifacts └─ High-frequency noise SE-AlexNet Problem: ├─ Learns shadows as features! ├─ Attention amplifies noise ├─ Misidentifies artifacts ├─ Result: 77.40% accuracy (collapse!) What Happened? SE blocks learned: ├─ Dark shadow = identity marker ├─ Bright highlight = face feature ├─ Background = contextual clue → Fooled by non-biometric signals! Mean FNR: 0.817 (very high!) (81.7% of genuine users rejected)

Why ULBP Remains Stable

Face ULBP: Only -2.7% Degradation
Key Property: Comparison-Based
ULBP compares neighbors to center: b_k = (neighbor_k ≥ center) ? 1 : 0

Why This is Robust:
✓ Relative comparison: Independent of absolute intensity
✓ Monotonic invariance: Stretching histogram doesn't change LBP
✓ Local analysis: 3×3 neighborhood ignores global shadows
✓ Unlabeled learning: No "learning" of shadows as features

Example:
In NIR: Neighborhood [100, 105, 110, 120, ...] vs center 120
→ Binary: [0,0,0,1,...] (same pattern)

In RGB with shadow: [100, 105, 80, 120, ...] vs center 120
→ Binary: [0,0,1,1,...] (DIFFERENT pattern)

But ULBP captures local texture, not global artifacts → Only minor degradation (-2.7%)
